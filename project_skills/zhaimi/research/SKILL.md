# zhaimi-research — 研究员技能包

> 适用 profile：researcher
> 依赖公用技能：`web-scraping`、`research`（见相对路径引用）

## 触发条件

用户在以下场景调用 researcher profile：
- "帮我看看这个选题值不值得做"
- "分析一下这个竞品账号"
- "拆解这篇爆款笔记"
- "从这些评论里挖选题"
- "数据分析 / 调研"

---

## 技能 1：选题评分（topic-scoring）

### 触发
- "这个选题能火吗 / 帮我评分"

### 流程
1. **搜索量验证**：`web_search` 搜选题关键词，看搜索结果量级和爆款情况
2. **痛点强度评估**：判断对应的焦虑程度（痒点/痛点）
3. **竞争度分析**：同赛道对手做这个选题的频次和水平
4. **转化潜力评估**：看完笔记最自然的下一步是咨询/收藏/划过
5. **汇总输出**

### 评分维度（各 1-10）
- 搜索量、痛点强度、竞争度（越低分越容易做）、转化潜力、可执行度

### 宅咪业务边界检查
- [x] 跟上门洗护/临港服务直接相关？不相关扣 3 分
- [x] 能自然植入宅咪服务？

### 综合判定
- ≥ 40/50 → 强烈推荐
- 30-39 → 推荐
- 20-29 → 观望
- < 20 → 放弃

### 输出格式
```
【选题评分报告】
选题：{题目}
搜索量：X/10 — {说明}
痛点强度：X/10 — {说明}
竞争度：X/10 — {说明}
转化潜力：X/10 — {说明}
可执行度：X/10 — {说明}
综合：X/50 | 推荐等级：{等级}
选题方向建议：{具体建议}
```

## 技能 2：竞品分析（competitor-analysis）

### 触发
- "分析这个账号 / 竞品 / 看看对手在发什么"

### 流程
1. **赛道扫描**：web_search + Chrome 搜索目标关键词
2. **内容策略拆解**：选 3 个代表性账号拆人设/选题/封面/标题/互动/私域钩子
3. **爆款归因**：每篇爆款回答"为什么爆"
4. **差异化机会识别**：不做 / 调整做 / 抢先做 / 新做

### 输出格式
```
【竞品分析报告】
分析对象：{目标}
赛道概况：竞争度{高/中/低}
代表性账号：3 个
差异化机会：{具体选题方向}
```

## 技能 3：爆款笔记拆解（viral-deconstruct）

### 触发
- "拆解这篇 / 拉片 / 为什么能火"
- 用户发来笔记 URL

### 五维拆解
- **标题**：字数/钩子类型/搜索词/公式提取
- **封面**：风格/配色/布局
- **钩子**：开头技巧/信息差
- **正文**：结构脉络/信息密度
- **评论区**：高赞/待答问题/置顶

### 输出
- 拆解报告 + 爆款公式 + **宅咪适配版本**（每个维度都要改写为宅咪能用）
- 不输出"观后感"，输出可复用的模板

---

## 技能 4：评论洞察（comment-insight）

### 触发
- "分析这些评论 / 弹幕出选题 / 评论区挖选题"

### 分类模型（SOP-B 继承）
| 分类 | 典型表达 | 示例 |
|------|----------|------|
| 痛点 | 我家猫XXX怎么办 | "我家猫洗澡跟杀猪一样" |
| 需求 | 有没有XXX服务 | "临港有人上门洗猫吗" |
| 选择 | XXX和XXX哪个好 | "上门洗和店里洗哪个干净" |
| 吐槽 | 上次去XXX太差了 | "上次洗猫应激了" |

### 评分 + 筛选
- 痛点强度 1-5 + 可回答度 1-5
- **选题池**：痛点≥3 且 可回答度≥4
- **观察池**：痛点≥3 且 可回答度=3

### 输出
- 分类统计 + 选题池 + 每条的改写标题 + 切入角度

---

## 通用红线（全部 4 技能共用）

- [ ] 输出的是**可执行的方案**，不是分析报告
- [ ] 不编造数据（搜索量说"未查到"而不是编数字）
- [ ] 不写性别限定词
- [ ] 0→1 阶段所有建议导向"可执行"
- [ ] 爆款拆解必须有"宅咪适配版"（不能只拆不建）
